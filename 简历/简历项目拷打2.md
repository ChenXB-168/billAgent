 L4 资深面试官质疑链（全面版）

定位：对标资深工程师（T8-T9 / P7 / 2-1）二面技术深挖
核心逻辑：不预设你包装，但要求每一步决策有因果链、每个设计知道边界在哪
使用方式：逐条自答，能答的整理成面试话术，答不上的要么补代码要么准备"当前版本没做，如果上生产我会这样处理"的兜底回答

模块一：架构与并发

Q1 · Worker 生命周期与资源管理

质疑："你的 Worker 是常驻协程还是每次任务新建？常驻的话它占什么资源？退出条件是什么？"

追问链：

- Worker 处理完任务后回到等待状态——如果永远等不到新任务，它占着事件循环但不干活，你怎么回收？
- 如果 Worker 协程里出现异常没捕获，会传播到事件循环吗？你做了全局 exception handler 吗？
- 4 个 Worker 同时忙的时候，第 5 个任务来了——排队还是拒绝？排队的话排多久？

面试官意图：确认你理解协程不是"起了就不管"，有生命周期管理问题。

Q2 · Queue 的边界条件与背压

质疑："asyncio.Queue 默认无界。你设了 maxsize 吗？没设——内存涨到多少会爆？设了——满了 Orchestrator 阻塞，新请求进不来，你怎么办？"

追问链：

- 你有没有背压机制？Queue 超阈值时 Orchestrator 停止派发或降级？
- Queue 里传的是对象引用还是序列化数据？如果是引用——Worker 改了对象，Orchestrator 侧看得到吗？这算不算隐式共享状态？
- 如果 Worker 消费速度远低于派发速度（比如统计 Worker 做复杂聚合），Queue 持续堆积——你怎么感知？怎么处理？

面试官意图：Queue 是你架构的核心组件，他要看你是不是只用了"put/get"两个 API 还是真想过生产级用法。

Q3 · 单事件循环的并发本质

质疑："你说'并发'——asyncio 是协作式多任务，不是抢占式。你的 BM25 检索、FAISS 向量计算是 CPU 密集的，执行期间事件循环被阻塞，其他 Worker 怎么办？"

追问链：

- 你测过 FAISS 检索期间事件循环的阻塞时长吗？
- 有没有考虑过把 CPU 密集部分丢到 
"run_in_executor"？为什么没做？是没必要还是不知道？
- 如果以后加一个"导出月度报表"（大量数据聚合 + 格式化），单事件循环撑得住吗？

面试官意图：确认你知道 asyncio 的边界，不是所有场景都适合协程。

Q4 · Orchestrator 单点问题

质疑："Orchestrator 是唯一入口和调度中心。它挂了整个系统停。你的恢复机制能自动拉起吗？还是人工重启？"

追问链：

- 重启后 Orchestrator 从哪恢复状态？任务表还是 LangGraph checkpoint？以谁为准？
- 如果旧 Orchestrator 没完全死（假死但还占着资源），新实例怎么避免冲突？
- 你有没有做过进程守护（systemd / supervisor / nohup）？

面试官意图：单点故障是基本功，他要确认你有这个意识，不要求你有完美方案。

Q5 · LangGraph 使用深度

质疑："你的图里有循环吗？有条件边？有人机交互中断？如果都没有——就是一条直线，为什么用 LangGraph 不用手写状态机？"

追问链：

- 你用了 Checkpointer——存的粒度是什么？每个节点存一次还是只在关键步骤存？
- 你用了 reducer 吗？还是全默认覆盖？全默认跟普通 dict 有什么区别？
- 如果去掉 LangGraph，核心逻辑剩多少行？去掉后你丢的到底是什么能力？

面试官意图：判断 LangGraph 是真需要还是简历需要。

模块二：数据真实性与指标定义

Q6 · 投递延迟 vs 端到端延迟

质疑："你说 P95 94.9ms→0.1ms——这是投递延迟对吧？端到端（用户输入到结果返回）你测了吗？P50/P95 各多少？"

追问链：

- 如果端到端是 2 秒，投递 0.1ms 这个数字在简历里会不会误导？
- 你测的时候并发数是多少？单请求还是多请求同时打？

面试官意图：确认你不混淆微观指标和宏观性能，不拿投递延迟包装成系统性能。

Q7 · 性能优化的因果链

质疑："你说三步顺序不可换——怎么证明的？有 profile 数据吗？先并行再改事件驱动会怎样？"

追问链：

- 26~29s 冷启动——这 26 秒在干嘛？加载模型？启动解释器？import 依赖？你 profile 过时间分布吗？
- 数据库改 WAL——你测过多协程并发写吗？遇到过 
"database is locked" 吗？

面试官意图：确认你的优化是数据驱动的，不是拍脑袋。

Q8 · 评测样本量

质疑："hit@3 100% / recall@5 92.86%——13 条查询。谁写的？你自己吧？让无关人员问 50 条还能 100% 吗？"

追问链：

- 你的笔记库实际多少条文档？如果只有几十条，hit@3 100% 说明不了什么。
- 44 个测试文件——测的什么？覆盖率多少？pytest --cov 跑过吗？

面试官意图：确认评测不是自嗨，有基本的方法论意识。

模块三：可靠性与一致性

Q9 · 幂等性

质疑："崩溃恢复后重派任务。如果 Worker 已经执行了一半（比如账单写了一条但结果没返回），你重派——账单写两次。你怎么防止？"

追问链：

- 你的任务有幂等键吗？是什么？任务 ID？用户指令哈希？
- 写操作前查重？还是数据库唯一索引？
- 如果重派时 Worker 其实还在执行（没死只是慢）——两个实例同时写怎么办？

面试官意图：幂等是基本功，没做过的人答不上来。

Q10 · 双重状态的一致性优先级

质疑："LangGraph checkpoint 和任务表两套状态。重启后如果 checkpoint 说完成、任务表说 pending——信哪个？你定义过优先级吗？"

追问链：

- 如果以任务表为准——checkpoint 的意义是什么？只是缓存？
- 两套状态更新的顺序是什么？先更哪个？第一步成功第二步失败——中间态怎么处理？

面试官意图：双重持久化如果没有明确主从，就是定时炸弹。

Q11 · SQLite 并发与崩溃

质疑："WAL 模式下 asyncio 多协程同时写——会锁吗？你遇到过 
"database is locked" 吗？"

追问链：

- 你的写入是串行化了（单协程专门写）还是各 Worker 自己写？
- SQLite 在 SIGKILL 时 WAL 文件可能损坏——你做过完整性校验吗？损坏了怎么恢复？
- 你说"已通过进程强杀验证"——几次？什么信号？覆盖了哪些中间态？

面试官意图：SQLite 是嵌入式数据库，并发和崩溃恢复的细节能区分"用过"和"真懂"。

模块四：权限与隔离

Q12 · 权限机制 vs 约定

质疑："你说只有记账 Agent 能写账单。它怎么阻止其他 Agent 写？是靠代码 if 还是 OS 级隔离？"

追问链：

- 统计 Worker 代码里直接 
"sqlite3.connect().execute('INSERT INTO bills...')" 能拦住吗？
- 你的"权限隔离"如果只是代码约定——那跟"大家都自觉不写"有什么区别？
- 如果以后把某个 Worker 拆到独立进程——你的权限模型还能工作吗？

面试官意图：同进程内没有强制访问控制，他要看你知不知道这个边界。

Q13 · 工具网关

质疑："工具调用统一经网关——网关是独立进程还是同进程函数？Worker 能绕过网关直接调工具吗？"

追问链：

- 网关做了什么？参数校验？权限判断？耗时统计？如果只做了一两样，其他为什么没做？
- MCP 服务返回错误（500/超时）——网关怎么处理？重试？降级？超时设的多少？

面试官意图：确认网关不是"又包了一层函数"而是有实际管控能力。

Q14 · 防幻觉的边界

质疑："数字白名单——模型输出'约50块'怎么处理？正则提取到 50，SQL 算出来 49.5，在不在白名单里？"

追问链：

- 白名单是精确匹配还是范围匹配？范围多少？谁定的？
- 模型输出中文数字（"五十"）覆盖了吗？
- 写操作不自动重试——读操作重试吗？读到了脏数据怎么办？

面试官意图：防幻觉方案不能只覆盖理想情况，他要看到边界处理。

模块五：扩展与演进

Q15 · 水平扩展路径

质疑："如果要支持 10 个用户同时用，你架构改什么？Queue 换什么？SQLite 换什么？"

追问链：

- asyncio.Queue 换 Redis Stream 要改多少代码？接口兼容吗？
- SQLite 换 PostgreSQL——你的 SQL 要重写吗？用了什么 ORM 还是裸写？
- Worker 跑在多个进程里——你的 Queue 通信怎么跨进程？

面试官意图：看你的架构是"写死了"还是"留了扩展口"。

Q16 · 新功能接入成本

质疑："如果要加第 5 个 Worker（比如'账单导出'），你改哪里？改配置文件还是改 Orchestrator 代码？"

追问链：

- 依赖关系现在是硬编码的还是可配置的？
- 新 Worker 的工具接入要走适配器吗？还是直接写？
- 加一个新功能从开发到上线你估多久？

面试官意图：验证你的架构对变化的适应能力。

Q17 · MCP 服务可用性

质疑："你的 3 个 MCP 常驻服务如果有一个挂了——系统怎么办？Orchestrator 能感知吗？用户看到什么？"

追问链：

- 有没有健康检查？多久检测一次？
- 挂了之后重试几次？退避策略？
- 如果这个 MCP 是记账必需工具——降级方案是什么？

面试官意图：外部依赖不可用是生产常态，他要看你有没有基本容错。

模块六：选型对比

Q18 · 为什么不用 AutoGen / CrewAI

质疑："AutoGen 天然支持多 Agent 对话协商，CrewAI 有角色扮演和任务委派——你评估过吗？为什么不用？"

追问链：

- 你的场景为什么不适合对话协商模式？
- 如果以后要加"Agent 之间互相讨论"的能力——你的架构能加吗？

面试官意图：确认你选型是思考过的，不是"LangGraph 火就用 LangGraph"。

Q19 · 为什么不用 Celery / Redis Queue

质疑："Celery 是成熟的异步任务队列，有持久化、重试、Worker 池、监控。你用 asyncio.Queue 的理由是什么？"

追问链：

- 是部署简单？不需要分布式？还是没考虑过？
- 如果以后要跨机器——你 Queue 怎么迁移？

面试官意图：asyncio.Queue 是内存级的，他要看你知道这个限制。

Q20 · 为什么不用 FastAPI 做服务化

质疑："你说单机运行——如果要做成 API 服务供前端调用，你的架构能直接套吗？还是要大改？"

追问链：

- Orchestrator 做成 endpoint？Worker 做成后台任务？
- 用户请求进来后断开连接了——任务还在跑吗？结果怎么拿回？

面试官意图：确认你的项目是"脚本"还是"有服务化潜力的系统"。

模块七：简历叙事与概念准确性

Q21 · "多 Agent 系统"的定义

质疑："你的 4 个 Worker 跑在同一进程、同一事件循环里。这跟'起 4 个函数'本质区别是什么？你为什么管它叫多 Agent？"

追问链：

- Worker 有独立身份吗？有独立记忆吗？能拒绝任务吗？
- 如果去掉 Queue 直接函数调用——用户感知到什么差别？

面试官意图：术语准确性。过度包装会被追问穿帮。

Q22 · "RBAC 权限模型"的实现深度

质疑："简历写了 RBAC——你建了角色表、权限表、用户表吗？还是几个 if-else？"

追问链：

- 如果是 if-else——简历写 RBAC 是不是过度包装？
- 你的权限模型能动态配置吗？还是写死在代码里？

面试官意图：确认你用的术语跟实际实现匹配。

Q23 · "已通过进程强杀验证"的诚实度

质疑："几次？什么信号？覆盖了哪些状态？有没有记录验证结果？"

追问链：

- SIGKILL 和 SIGTERM 行为一样吗？你两种都测了？
- 强杀时任务在 Queue 里、在 Worker 里、在写数据库——各测过吗？

面试官意图：确认"已验证"不是一句正确的废话。
