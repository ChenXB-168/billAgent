### 项目经历

* **2026/06 - 至今**　　**Python 个人项目**　　**消费管家智能体（billAgent）· 多 Agent 协作系统**

  解决问题：现有记账工具以流水记录为主，消费前缺少预算依据、消费后缺少分类评估。
  方案：用 LangGraph 编排多个分工不同的 Agent，工具调用统一到一个入口；数值计算全部走 SQL，模型只负责理解意图和组织语言。
  产品：面向个人记账场景，单句输入即可完成记账、预算查询、同类比价与消费评估；单机运行，约 2.2 万行 Python。
  GitHub：https://github.com/ChenXB-168/billAgent

  项目内容：

  * **架构设计方面**：针对单 Agent 承担全部业务导致职责混杂、写权限难以收敛的问题，按消费对话场景的基类业务拆分为 1 个编排器与 4 个专职子 Agent（记账 / 统计 / 比价 / 理财）；写库权限仅授予记账 Agent（同进程内的工程约定，非 OS 级隔离），各 Agent 业务逻辑独立、可分别替换与测试。
  * **工具接入方面**：针对工具调用分散在各处、鉴权与参数校验等治理逻辑需在每个调用点手写且容易遗漏的问题，建一层统一的工具接入层——工具元数据集中登记，调用统一走单一入口，鉴权、参数校验、写操作审计与超时在该层统一施加；新增一种调用协议只需注册适配器，调用方无需改动。
  * **性能优化方面**：针对多任务端到端耗时过长，逐层定位后改造三处瓶颈：消息投递由轮询改事件驱动、工具服务由按需启动改常驻（消除冷启动）、任务由逐个派发改整批并发；端到端耗时明显下降。
  * **可靠性方面**：针对进程异常终止导致任务状态丢失、已完成任务被重复执行的问题，实现任务状态持久化与重启后自动对账（按任务号核验业务表，判定完成或重投）：未完成任务继续执行、已完成任务不重复执行。
  * **防幻觉与写操作保护方面**：金额与统计由 SQL 计算，模型仅负责语言组织；回复发出前逐个核对数字与计算结果，越界则重写一次、仍不通过则回退模板渲染，使主要数字可回溯到计算结果；写操作以任务号做幂等校验并配合重启对账，避免重复记账。
  * **记忆与检索方面**：笔记库与长期记忆均采用关键词 + 向量双路检索——笔记库按结果排名融合（两类分数不可比），长期记忆按权重打分并叠加口语时间信号；单通道不可用时自动降级为纯关键词检索。
  * **质量评测方面**：建立单元测试、集成 / 端到端、专项评测三层体系：单元测试 **566 条（33 个文件）当前全部通过**，业务代码语句覆盖率 **78%**，覆盖编排调度、4 个子 Agent、工具平台、模型接入、记忆检索、可观测与 WebUI（零外部依赖、可离线跑，并接入 GitHub Actions 自动回归）；集成与端到端在 MCP / 模型链路下做落库硬校验；另做检索专项评测 13 条查询（hit@3 100% / hit@1 61.54% / recall@5 92.86%，样本偏少，仅作回归基线）。
