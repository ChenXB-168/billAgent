### ⬜ 必改-5 · 技能栏 `LangGraph` 孤零零一个词 —— 有误导性

**在 Word 里搜**：`Agent 框架与协议：LangGraph、MCP / FastMCP（自建 3 个常驻MCP服务）`

**现在的问题**（★ 由本人自查发现，经代码核实）：

**实际实现是「LangGraph 只做编排 + 自建消息总线做 Agent 通信」，子 Agent 是各自独立编译的 Graph，不是 LangGraph 子图。** 但技能栏只写了一个 `LangGraph`——面试官会**默认"你的多 Agent 是 LangGraph 实现的"**，接着问"用子图吗""State 怎么共享"，而你答"我没用子图"时，**听起来像在回避**。

**更重要的是**：**「自建消息总线」是整份简历里最被低估的亮点，现在一个字都没写。** 不用子图不是缺陷——它是"判断了框架边界、补上了框架缺的部分"的证明（详见下）。

**改成**：

```
Agent 框架与协议：LangGraph（编排层：StateGraph / 条件边）、自建 A2A 消息总线（Agent 间通信）、MCP / FastMCP（自建 3 个常驻服务）
```

**为什么这么改**：① 显式界定 LangGraph 的作用范围，防追问；② 把"自建消息总线"写出来；③ 一行里体现"两层分离"的架构判断。

**必须同步准备的追问**（改完简历后一定会被问）：

> **问：你为什么不用 LangGraph 自带的子图 / Supervisor？**
>
> 答：用 LangGraph 做**编排层**（四节点 + 条件边），子 Agent **没做成子图**，是独立编译的 Graph + 自建消息总线。四个理由：
>
> ① **生命周期不同**：子图生命周期绑在图执行内，一次 `ainvoke` 结束就没了；**我的子 Agent 是跨请求常驻 worker**。
> ② **状态归属不同**：子图共享父图 State、生命周期跟图绑定；**我的任务状态必须落独立表**（`task_state.db`），要支持崩溃后按 `task_id` 对账重投。
> ③ **调度粒度不同**：子图是"父图调度一步、子图整体跑完"，**没有中间的任务级控制点**；我需要按 DAG 分层派发、乱序收集、**每个任务独立重试**。
> ④ **通信语义不同**：`langgraph-supervisor` / handoff 的前提是 **Agent 之间"控制权转交"**（串行语义）；**我的 4 个任务可能同时执行、各自独立重试、乱序返回**，handoff 表达不了"并行 + 独立失败域"。
>
> **如果我的场景只是"单次请求内跑几个无状态子任务"，我会直接用子图——那更省事。**
