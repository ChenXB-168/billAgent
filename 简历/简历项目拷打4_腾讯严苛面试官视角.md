## 第 0 章 · 面试官的元逻辑（通用，任何轮次都用）

**六把刀**：破坏者思维（怎么搞死它）/ 规模外推（放大 100 倍）/ 等价替换（去掉它）/ 概念对齐（这词到底什么意思）/ 因果链追溯（凭什么这么说）/ 边界条件（happy path 之外）。

**我会点开你的 GitHub**（简历 `:4`、`:16` 两处链接，且是个人项目）：README 前 50 行 → 对简历数字 → 抽 3 个最硬断言 → 看根目录整洁度。

**轮次分工**（本版核心）：
| 轮次 | 谁来面 | 主要考什么 | 你的风险 |
|---|---|---|---|
| **一面** | 同组高级工程师/组长 | 真实性、基本功、表达、能不能干活 | 讲不清、基础不过关 → 挂 |
| **二面** | 技术骨干 | 项目深度、架构、边界、代码级 ownership | 名实不符、深度不够 → 挂 |
| **三面** | 资深/交叉/主管 | **判断力、前瞻性、模糊需求、影响力、潜力** | 只会解释不会决策 → 定级低 |

> 注意：**一/二面考"你做过什么"（可准备），三面考"你遇到没做过的怎么办"（难准备）。** 本版前三章是"解释已做"，第三章新增部分是"面对未做"。

# 第 0.5 章 · 简历七条原文 → 逐条即时拷问（读简历阶段）

## 补充专章 · 优雅关机 / 进程退出防御（M23 / D26）

> **为什么单列**：优雅关机是"崩溃恢复"的**对偶面**——崩溃是"来不及关"，优雅关闭是"主动关"。二者共同构成"进程生命周期可靠性"。**面试官一定会问**：你只测了强杀（cold kill），那"主动关"呢？关了之后资源释放干净吗？关到一半的任务怎么办？
> **此章与二面 Q39（interrupted vs cancelled）、Q44（强杀验证）互补**，建议对照看。
> **先科普**：所谓"优雅关机"（graceful shutdown），指进程收到"要关了"的信号后，**不靠 OS 强杀**，而是自己有序地：① 停止接新任务 → ② 处理/中断在途任务 → ③ 落状态 → ④ 释放资源（子进程、连接）→ ⑤ 退出。**关键点**：Python 里 `SIGTERM`（`kill -15` / `docker stop` / 关机）的**默认行为是直接终止进程**——不抛异常、不执行 `finally`、不跑 `atexit`（依据 `webUI/app.py:99-102`），所以不做处理就会**留下孤儿进程**。
