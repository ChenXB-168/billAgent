# 16 · 价位查询能力方案（M18 · price 双模式）（梳理稿，未实施）

> **状态**：✅ **已实施**（2026-10-08：P0–P3 全部落地；L1 **491 → 497 passed**、`contract_check` FAIL 0）
> **日期**：2026-10-08
> **触发**：用户实测「我想去唱歌，预算多少合适」——M17 已能规划 `price + stat + finance`，
> 但 `price_agent` 仍要求"必须有用户金额"，**价位咨询链路在子 Agent 处断裂**。
> **结论先行**：**`price_agent` 增设「价位查询」双模式——有品类、无金额时仍查 `city_price`，
> 返回该品类**本地参考均价**（不做溢价率判断）；入参契约不变。**

## 一、需求说明（要改什么）

### 1.1 真实诉求

| # | 用户输入 | 期望行为 | 改造前 |
|---|---|---|---|
| **R1** | "我想去唱歌，预算多少合适" | 给出**该品类本地参考价位**（+ 预算余额 + 建议） | ❌ `price` 缺金额 → 主 Agent 追问"金额"（把决策咨询当成比价缺参） |
| **R2** | "买衣服花了几百"（有品类、金额模糊） | 给参考价位 + 引导补具体金额 | ❌ 直接失败："未识别到有效消费金额" |

### 1.2 本方案不做什么（范围边界）

- ❌ **不改** `price_agent` 的入参契约（`raw_segments: List[str]` 不变）
- ❌ **不改** `task_plan` 结构 / A2A / 主 Agent 的四档决策（M17 已就绪）
- ❌ **不做** "智能推荐预算区间"（那是 `finance` 的领域，本方案只提供**品类参考均价**这一事实）
- ❌ **不编造** 参考价位：查不到 `city_price` 仍如实失败

## 二、架构结论：`price` 的双模式

```
price（比价能力）
  ├─ 模式 A【比价】  ：有金额 → 查均价 → 算溢价率 → 判断"贵不贵"      （原有）
  └─ 模式 B【价位查询】：无金额、有品类 → 查均价 → 返回"参考价位"      （M18 新增）
                        └─ 不做溢价率判断（无用户金额可比），并引导补金额
```

**关键判断**：

- **能力其实早已存在**（`city_price` 表存有各品类基准均价），**只是被"必须有用户金额"的前置拦截卡住**；
- 因此**不需要新数据源、不需要新工具**，只需在 `execute_node` 里把「无金额」从"失败"改为"换模式"。

**与 M17 的衔接**：

| M17 侧 | M18 侧 |
|---|---|
| `fit_level=inferable` → 可规划无金额的 `price` | `price_agent` 能承接无金额输入 → 返回参考价位 |
| 契约表 `price.required` | 由 `["amount"]` → `[]`（**否则主 Agent 会判缺参拦下**） |

> **两者缺一不可**：只有 M17 会"规划了但子 Agent 失败"；只有 M18 则"子 Agent 支持了但主 Agent 仍判缺参"。

```
第 0 步（契约先行）

      └─ 验收：e2e/单测「有品类无金额」→ success=True + premium_rate=None + 参考均价
```

## 六、风险点

| # | 风险 | 说明与对策 |
|---|---|---|
| **R-1** | **既有用例编码旧行为** | 3 条用例断言"price 缺金额"与"amount=0 即失败"→ **必须同步更新**（否则 CI 红）。**这是行为变更的正常代价，不是回归** |
| **R-2** | **价位查询被误用为"比价"** | 查询模式返回 `premium_rate=None`，渲染层据此分岔；若渲染未改会 dump dict → **P4 与 P2 必须同批** |
| **R-3** | **`finance` 误以为拿到了"溢价结论"** | 上游 `finance` 注入的是 `price_result` 原文；查询模式下**无 `consume_level`/`conclusion`** → `finance` 需按"仅知参考价位"表述（提示词已含"暂缺数据"处理，无需改代码） |
| **R-4** | **无金额时金额兜底误伤** | `parse_llm_extract_output` 对"原文有数字但 LLM 漏提"会正则兜底取**首个数字**；若用户说"我想去唱歌 3 个人"，会把 3 当金额 → **已有既存行为**，本方案不改变；如需治理另立缺陷 |
| **R-5** | **查不到基准价仍失败** | 如实失败（`暂无城市基准物价数据`）—— **不编价格**，符合"数字可信"红线 |
