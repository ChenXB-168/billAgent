## 1. 部署形态

**一句话**：**单进程 Python 应用 + 本地 Ollama 服务 + MCP 常驻服务 ×3（✅ M3 已完成 2026-09-02）**，全部跑在一台机器上。

```
┌──────────── 单机（Windows / 开发环境）────────────┐
│                                                     │
│  ┌─ 主进程（Python）───────────────────────────┐   │
│  │  入口：main.py（CLI）或 webUI/app.py（WebUI） │   │
│  │  ├─ orchestrator（随请求 ainvoke）            │   │
│  │  └─ 4 个 worker：asyncio 协程（非进程！）      │   │
│  │       bill / stat / price / finance           │   │
│  │  └─ start_mcp_servers()：bootstrap 拉起常驻服务│   │
│  └───────────┬──────────────────────────────────┘   │
│              │ HTTP 常驻（M3；BILLAGENT_MCP_STDIO=1 回滚）│
│  ┌───────────▼──────────┐   ┌──────────────────┐   │
│  │ MCP 常驻服务 ×3       │   │ Ollama 服务       │   │
│  │ sql / llm_base /      │   │ 127.0.0.1:11434  │   │
│  │ llm_finance           │   │ 本地 1.8B 模型    │   │
│  │（端口 MCP_SERVER_PORTS）│                    │   │
│  └──────────────────────┘   └──────────────────┘   │
│              │                                       │
│  ┌───────────▼──────────────────────────────────┐   │
│  │ 磁盘：database/bill.db、ragKnowledge/*.pkl、   │   │
│  │       logs/（app.log / audit.log）             │   │
│  └──────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────┘
```

| 关键事实 | 说明 | 代码位置 |
|---|---|---|
| **worker 是协程，不是进程** | `asyncio.create_task(coro)` 拉起 4 个常驻协程 | `bootstrap.py:156-164` |
| 进程数 | 主进程 1 个 + MCP 常驻服务 3 个（✅ M3 常驻化后：`subprocess.Popen` 随 `bootstrap.start_mcp_servers()` 拉起，非按需；回滚开关 `BILLAGENT_MCP_STDIO=1`） | `mcpGateway/client.py` + `startup/bootstrap.py` |
| 外部中间件 | **无**（无 Redis、无消息队列、无容器） | — |
| 网络监听 | WebUI `127.0.0.1:7860`（仅本地） | `start_webui.bat:11` |

> ⚠️ **易错点**：常说"4 个 worker"容易被理解为 4 个进程——**实际是 4 个 asyncio 协程**，
> 这是约束 **C1**（`01_需求与约束` §7.2）的由来，也是"持久化 ≠ 跨进程恢复"的原因。

## 2. 环境依赖

### 2.1 必需项

| 依赖 | 版本/位置 | 缺失后果 | 来源 |
|---|---|---|---|
| **Python** | 3.x（venv 隔离） | 无法启动 | `install_cpu.bat:20` |
| **Ollama 服务** | `127.0.0.1:11434`，模型 `qwen-bill-1.5-1.8b-q4km` | 本地基线不可用 | `config.py:46-48` |
| **CPU 版 PyTorch** | 需**显式指定** `--index-url .../cpu` | 误装 CUDA 版会体积爆炸且本机无法用 | `install_cpu.bat:31` |
| **项目依赖** | `requirements.txt`（清华源加速） | 无法启动 | `install_cpu.bat:35` |
| **Embedding 模型** | `modelService/embedding` | 长期记忆 / RAG 不可用 | `config.py:24` |

### 2.2 可选项（不配也能完整跑通）

| 依赖 | 作用 | 不配时的行为 |
|---|---|---|
| 外部 LLM（`BILLAGENT_EXT_LLM_BASE_URL` + `API_KEY`） | 强模型增强编排与理财表达 | **自动回退本地 1.8B**（`EXTERNAL_LLM_ENABLED=False`） |

> 这是 `01_需求与约束` §6「**本地基线可交付**」红线的部署侧体现。

### 2.3 安装步骤（`install_cpu.bat`）

```
1. python -m venv venv                                  # 首次创建虚拟环境
2. call venv\Scripts\activate.bat
3. pip install --upgrade pip -i 清华源
4. pip install torch torchvision torchaudio --index-url .../cpu   # 关键：CPU 版
5. pip install -r requirements.txt -i 清华源
6. 验证：python -c "import torch; print(torch.cuda.is_available())"  # 应为 False
```

## 3. 启动顺序

### 3.1 As-Is（M2/M3 前，`bootstrap_all()`，`bootstrap.py:130-166`）

| 步 | 动作 | 代码 | 说明 |
|---|---|---|---|
| 1 | **数据库连通校验** | `db.execute_sql("SELECT 1;")` | 含建表？⚠️ 见下文注 |
| 2 | **用户文档索引对账** | `load_user_docs()`（M8 起） | 同步构建/对账；失败仅 WARNING，首次检索时自动重建（不阻断启动） |
| 3 | MCP 客户端初始化 | 仅打日志 | 实际**无动作**（MCP 是调用时拉子进程） |
| 4 | **A2A 总线清理** | `a2a_bus.clear_all()` | 清残留消息 |
| 5 | 注册 Agent + **拉起 4 个 worker 协程** | `asyncio.create_task` | 常驻消费循环 |

> **注**：建表由 `database/init_db.py` 的 `init_all_tables()` 负责，**需单独执行**（`python database/init_db.py`），
> 不在 `bootstrap_all()` 内——这是首次部署的**隐式前置步骤**，容易漏。

### 3.2 现启动顺序（✅ M3 已完成，2026-09-02 = 当前 `bootstrap_all()`）

MCP 已由 **stdio 短连接**改为 **Streamable HTTP 常驻服务**：

```
1. 数据库连通校验（db.execute_sql("SELECT 1")）
2. 用户文档索引对账（load_user_docs()，★M8：失败不阻断启动，首次检索自动重建）
3. ✅ 启动 MCP 常驻服务（start_mcp_servers()）—— subprocess.Popen 拉起 3 个服务 + initialize 探活（120×1s）
4. 🔧 孤儿任务恢复（D2，仍 To-Be）—— recover_orphans() 扫描 running → submitted/failed（04 §3.1 修订版）
5. A2A 总线清理（a2a_bus.clear_all()，M2 已事件化）
6. 注册 Agent + 拉起 4 个 worker
```

| 变化 | 影响 |
|---|---|
| MCP 服务常驻 | ✅ **已落地**：单次调用冷启动（原预估 +26~29s）**消除**；M2 实测 P95 投递延迟 0.31ms |
| 启动时间变长 | 服务进程随 bootstrap 拉起，**总启动略变慢、单次调用变快** |
| 新增进程存活依赖 | 主进程 `_probe_mcp_server` 握手探活；退出 `stop_mcp_servers()` 关闭（5s 宽限→kill） |
| 回滚 | `BILLAGENT_MCP_STDIO=1` 整体回滚 stdio 短连接（server 端配对） |

### 3.3 优雅关闭（`shutdown_system()`，`bootstrap.py:169-177`）

```python
SHUTDOWN_FLAG = True                      # worker 循环退出
for task in WORKER_TASKS: task.cancel()
await asyncio.gather(*WORKER_TASKS, return_exceptions=True)
```

| To-Be 增强（D2 / `08` §6 Q7） | 说明 |
|---|---|
| 在途任务标记 `interrupted` | 而非静默丢弃 |
| MCP 常驻服务的关闭 | 需随主进程退出而关闭（避免孤儿进程） |

## 4. 配置与密钥

| 项 | 方式 | 位置 |
|---|---|---|
| 路径常量 | 代码常量（项目相对路径） | `config.py:12-24` |

## 5. 备份与恢复

### 5.1 需备份的内容

| 对象 | 路径 | 丢失后果 | 备份优先级 |
|---|---|---|---|
| **账单数据库** | `database/bill.db` | **全部账目丢失**（不可重建） | 🔴 最高 |
| **用户文档库** | `userDocs/*.txt` \| `*.md` | 🔴 **用户原创笔记全丢，不可重建**（物价记录 / 省钱策略都是用户手写的） | 🔴 **最高**（2026-08-30 新增） |
| 长期记忆 pkl | `ragKnowledge/long_consume_mem.pkl`（M8 后该目录仅存此文件） | 记忆丢失（**FAISS 可由它重建**，反之不行） | 🟡 中 |
| 用户配置 | 含在 `bill.db` 的 `user_config` 表 | 需重新设置 | 🔴 高（随库备份） |
| 审计 / 运行日志 | `logs/` | 无（7 天自动轮转，本就不长期保留） | ⚪ 低 |

> **关键认知（2026-08-30 修订）**：
> ① **长期记忆**的 FAISS **不需要备份**——启动时由 pkl 重建（`04` §1.1）；
> ② **用户文档库**的索引（`userDocs/.index/`）**也不需要备份**——启动对账 `load_user_docs()` 按内容哈希由 `userDocs/` 原文自动重建（`04` §3.5.2；✅ **M8 已落地**，`11` §3 M8）；
> ③ 但 **`userDocs/` 原文必须备份**——它是用户手写内容，**丢了就真没了**（索引丢了能重建，原文丢了不能）。
>
> ⚠️ **M3.5 启用 WAL 后**：`bill.db` 会多出 `bill.db-wal` / `bill.db-shm` 两个文件，
> 直接拷贝 `bill.db` **可能漏掉尚未 checkpoint 的事务** → 备份须改用
> `sqlite3.Connection.backup()`，或先执行 `PRAGMA wal_checkpoint(TRUNCATE)`（见 §7 决策点 3）。

### 5.2 恢复步骤

```
1. 装环境（install_cpu.bat）
2. 停应用
3. 拷贝 bill.db 到 database/（覆盖）
4. 拷贝 long_consume_mem.pkl 到 ragKnowledge/（可选）
5. 启动 → bootstrap 自动校验 DB、重建 FAISS 索引
```

### 5.3 现有备份痕迹

`database/bill.db.bak_20260816` —— 此前**手工备份**的产物。
⚠️ **无自动备份机制**，建议至少提供一键备份脚本（见 §7 决策点 3）。

## 6. 健康检查与常见故障

| 症状 | 可能原因 | 排查 |
|---|---|---|
| 启动报 `no such table` | **未执行 `init_db.py`** | 先跑 `python database/init_db.py` |
| 首次 LLM 调用卡住很久 | MCP 子进程冷启动（**26~29s，待实测**——三个 server 均不加载 embedding/rerank 模型，疑似过时） | 已知瓶颈，To-Be 常驻化后消除 |
| 回复质量差 / 意图识别错 | 未配外部 LLM，走本地 1.8B | 配 `BILLAGENT_EXT_*` 环境变量 |
| `CUDA available: True` | 装错 PyTorch 版本（应为 CPU 版） | `install_cpu.bat:31` 重裝 |
| 长期记忆无效果 | `long_consume_mem.pkl` 缺失或 embedding 模型缺失 | 检查 `modelService/embedding` |
| WebUI 打不开 | 端口 7860 被占用 / 未启动 | 换端口或释放占用 |
| **两次记账重复入库** | 任务重投（当前无幂等） | D2 落地后由 `task_id` 幂等解决（`04` §3.2） |
