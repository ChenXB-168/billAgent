### 0.2 术语表

### 0.3 设计总原则（红线）
1. **Agent 之间不直接调用函数**，一律通过 A2A 总线异步通信；
2. **Agent 不直接访问数据库与 LLM**，一律通过 MCP 网关（`mcpGateway`）转发；
3. **业务能力（记账/统计/建议）沉淀在 `coreModules`**，Agent 只做编排与状态流转；
4. **记忆分长短两层**：短期记忆随会话、长期记忆跨会话；
5. **prompts 与代码分离**，Agent 的提示词全部外置在 `prompts/` 目录。

### 0.5 契约卡读法（本手册统一格式 · 2026-09-02 新增）

> 起因：M3（MCP 常驻化）施工连踩 5 坑，根因是**契约只写到"接口名"级**——没有签名约束、没有边界、没有上下游连接，导致"client↔server 成对契约""生产入口↔测试入口""异常契约随传输层变化"全部漏判。故本手册统一升级为下述格式。

每个模块的契约**一律由三部分组成，缺一不可**：

```text
① 模块边界卡  → 职责 / ✅能做 / ❌不能做（红线）/ 所有权 / 状态
② 接口表      → 每个接口：签名 · 职责 · 返回 · 异常 · 连接（上游← / 下游→）
③ 契约卡      → 仅跨模块接口展开：前置条件 · 后置保证 · 参数约束 · 边界红线
```

**接口表列定义（填写要求）**：

| 列 | 含义 | 填写要求 |
|---|---|---|
| 接口 | 符号名 | 与代码**逐字一致**（含大小写、下划线） |
| 签名 | `def` 行 | 含参数名 / 类型标注 / 默认值 / 返回类型，**照抄代码** |
| 职责 | 一句话 | 只写"做什么"，不写"怎么做" |
| 返回 / 异常 | 类型 + 抛出条件 | 异常必须写清**什么情况抛**、是否可重试 |
| **连接** | `← 上游调用方` / `→ 下游依赖` | **必填**，格式 `文件:函数`。这是改动时评估影响面的**唯一依据** |

> ⚠️ **连接列的用途**：改任何接口前，先看"上游调用方" = **回归范围**；看"下游依赖" = **联调范围**。跨模块的**成对契约**（如 client 传输方式 ↔ server 传输方式）必须在两端**互相登记**，只写一侧等于没写。

**三方对齐规则（红线）**：

| 对齐项 | 规则 |
|---|---|
| 模块划分 | 本手册 ↔ `03_逻辑架构.md` §2 模块清单**逐一对应** |
| 接口名 / 签名 | 本手册 ↔ **代码** 逐字一致 |
| 冲突时 | **以代码为准**，回改文档，并记入 §8.2 待确认项 |

## 4. 端到端调用链路（改动前先读）

一次"记账"请求的完整旅程（每一跳的接口定义见 §5）：

```text
用户输入
  └─> webUI / main.py（startup 引导）
        └─> orchestrator.plan_node
              └─ registry.invoke("llm.chat") ──意图解析──> task_plan（TaskSpec 列表，含依赖）
        └─> orchestrator.dispatch_node（★ 唯一派发者，按依赖分批）
              └─ 组装 task_data（四套差异，§5.1）
              └─ a2a_queue.send_task(target_agent, session_id, task_id, task_data)
                    │         ← task_id = 全局唯一路由键（§5.1 生成规则）
                    ▼
              （依赖决定串/并行：bill → stat/price → finance；M6 后依赖内并行）
              每个目标 Agent 的 worker：驱动自身图 → registry.invoke 取数/取 LLM
                    │         → reply_node 组装 final_struct（§5.1 5 字段）
                    ▼
              a2a_queue.send_result(task_id, json.dumps(final_struct))   # ★传输线 = final_struct 的 JSON 字符串（orchestrator 端 json.loads 还原）
        └─> orchestrator.wait_result_node
              └─ 只等待【自己派发的】task_id 的结果（超时 240s 抛 TimeoutError）
              └─ 若 finance 任务带前置结果：前置 Agent 结果已由 orchestrator 收齐并透传
        └─> orchestrator.collect_node → 汇总 → build_user_display_text → final_reply
  └─> 返回用户
```

> ⚠️ **拓扑红线（2026-09-02 修正，旧版歧义作废）**：
> 1. **orchestrator 是唯一派发者**，A2A 为**单层**结构（orchestrator ↔ 4 个子 Agent）。旧图"finance → 再派发 bill/stat/price"与代码、`03` 依赖 DAG 均不符，**作废**。
> 2. `wait_result` 只按 orchestrator 派发的 `task_id` 等待——若允许子 Agent 再派发，其子任务的 `task_id` **无人等待、链路不闭合**。因此红线 1 是**结构必然**（不是风格偏好）。
> 3. finance 的 `task_data` 携带 `bill_result/stat_result/price_result`（§5.1 第 4 套差异）= orchestrator **先派发前置 Agent、收齐结果后透传**给 finance，不是 finance 自己取数。
> 4. 所有子 Agent 的依赖关系只存在于 orchestrator 的 `task_plan`；子 Agent 之间互不感知、互不调用（违反即破坏环检测与超时模型的闭合性）。

| 跳 | 接口 | 契约位置 |
|---|---|---|
| orchestrator → LLM | `registry.invoke("llm.chat")` | §5.2 |
| orchestrator → 子 Agent | `a2a_queue.send_task` | §5.1 |
| 子 Agent → 数据库 | `registry.invoke("sql.read"/"sql.write")` | §5.2 |
| 子 Agent → LLM | `registry.invoke("llm.chat"/"llm.finance")` | §5.2 |
| registry → MCP 子进程 | `ExecutionEngine.invoke` → `MCPAdapter` → `exec_sql`/`llm_chat`/`finance_chat` | §5.2 |
| 子 Agent → orchestrator | `a2a_queue.send_result` | §5.1 |

### 5.1 A2A 消息契约（`mcpGateway/a2a_queue.py`）

**A2AMessageBus 接口**：

**边界卡**

| 项 | 内容 |
|---|---|
| 职责 | Agent 间通信的**唯一**通道（进程内 `asyncio.Queue` + `Event`） |
| ✅ 能做 | 任务投递、结果回传、按 `task_id` 路由、会话不匹配消息**旁路暂存**（`_parked`，不放回主队否则 `await get()` 忙循环） |
| ❌ 不能做 | 不做持久化（进程重启即失，D2 待解）；不做跨进程；**不解析业务语义** |
| 所有权 | `_task_queues` / `_result_events` / `_result_store` / `_parked` / `_shutdown_flag` |
| 状态 | ✅ 现役（**D4 去轮询已完成，M2 · 2026-09-01**：空闲唤醒 **36 次/秒 → 0**，P95 投递延迟 **30.9ms → 0.31ms**） |

**A2AMessageBus 接口契约**

| 接口 | 签名 | 职责 | 返回 / 异常 | 连接（← 上游 · → 下游） |
|---|---|---|---|---|
| `send_task` | `(target_agent: str, session_id: str, task_id: str, task_data: Dict[str, Any])`（**同步**） | 向目标 Agent 投递任务 | — | ← `orchestrator.dispatch_node`；→ `_task_queues[agent]` |
| `recv_task` | `async (agent_id: str, session_id: Optional[str] = None, max_wait=3) -> Dict[str, Any]` | 带超时接收（快路径 `get_nowait` + 慢路径 `wait_for`） | `dict` | ← 测试 / 业务；→ `_task_queues` |
| `recv_task_blocking` | `async (agent_id: str, session_id: Optional[str] = None) -> Dict[str, Any]` | Worker 常驻消费专用（**无限阻塞、零空转**） | `dict` | ← 4 个 `_bill/_stat/_price/_finance_agent_worker`；→ `_task_queues` |
| `send_result` | `(task_id: str, result: Any)`（**同步**） | Worker 回传结果；按 `task_id` 路由 | — | ← 4 个子 Agent `reply_node`；→ `_result_store` + `_result_events`（唤醒 `wait_result`） |
| `wait_result` | `async (task_id: str, timeout: int = 240) -> Any` | 编排器阻塞等结果，超时熔断（240s 对齐 `config.MODEL_TIMEOUT`） | `Any`；**超时抛 `TimeoutError`** 并清理该 task 的事件与结果 | ← `orchestrator.wait_result_node`；→ `_result_events[task_id]` |
| `clear_all` | `()`（**同步**） | 清空全部队列 / 结果缓存 | — | ← `bootstrap_all` 步骤 ④、测试 fixture；→ **重建**队列字典（规避 `asyncio.Queue` 跨 event loop 绑定，M2 教训） |
| `cleanup_session` | `(session_id: str)`（**同步**） | 会话清理 | ⚠️ **当前为 `pass`，空实现（预留扩展）**，调用方不可依赖其效果 | ← 暂无调用方 |
| `a2a_bus` | `A2AMessageBus` 全局单例 | 总线句柄 | — | ← 全仓 |

**契约卡：`send_result` ↔ `wait_result`（成对契约）**

| 项 | 内容 |
|---|---|
| 签名 | `send_result(task_id: str, result: Any)` ↔ `wait_result(task_id: str, timeout: int = 240) -> Any` |
| 路由键 | **`task_id` 是唯一键**——结果存储与唤醒均按它 |
| 前置条件 | `wait_result` 前须先 `send_task` 派发；两端 `task_id` 必须一致 |
| 后置保证 | 成功：`_result_store.pop(task_id)` 返回并清理事件；超时：清理事件与结果后抛 `TimeoutError` |
| 异常 | `wait_result` 超时抛 **`TimeoutError`**（注意：非 `asyncio.TimeoutError`） |
| 边界红线 | ① 不得给 `send_result` 加回 `target_agent` / `session_id`——会误导"按 Agent 路由 / 会话隔离"语义（M2 验收③已删）；② `clear_all` 必须**重建**队列而非逐个清空（跨 loop 绑定） |
| ⚠️ 勘误 | 旧版手册写 `send_result(target_agent, session_id, task_id, result)`——**M2 已删除死参数**，现签名为 `(task_id, result)` |

**同步 / 异步语义（调用方必须遵守）**：

| 方法 | 调用方线程 | 语义 |
|---|---|---|
| `send_task` / `send_result` / `clear_all` | **同步**（直接入队/存结果，不阻塞） | 可在任意上下文安全调用（worker 协程内、orchestrator 内皆可） |
| `recv_task` | **async** | 队列空时最多等 `max_wait=3` 秒（快路径 `get_nowait` + 慢路径 `wait_for`）；用于测试/非阻塞业务 |
| `recv_task_blocking` | **async** | 无限阻塞等下一个任务（事件化，零空转）；**仅限 4 个常驻 worker 使用** |
| `wait_result` | **async** | 阻塞到结果到达或超时（默认 240s）；超时抛 `TimeoutError` 并**清理该 task 事件与结果**（不可重等） |
| `cleanup_session` | 同步 | ⚠️ 空实现（`pass`），无效果——不要在业务路径中依赖它 |

> 异步方法必须运行在**与创建者相同的 event loop** 内（`asyncio.Queue` / `Event` 绑定创建时 loop，跨 `asyncio.run` 使用会崩——见 §8.3 踩坑 #2/#8）。

**task_data 四套差异**（`orchestrator/nodes.py` dispatch 组装，**两端强对齐**；类型见下表）：

| 目标 Agent | task_data 字段 |

#### 5.6.3.1 ContextManager（通用上下文组件 · `agents/context_manager.py`，M12/D6 落地）

**分层预算表**（`context_window - output_reserve` 为输入预算；system 固定预留 `min(400, 输入×15%)`；其余四层按比例静态分配，某层不参与时份额空置为宽松余量）：

| 层 | 比例（扣 system 预留后） | 溢出策略 | 红线 / 语义 |
|---|---|---|---|
| system | 固定预留 | 不可截 | 超限仅 WARN 保留全文（防幻觉角色规则）；组件不混入 layers（调用方分传 sys/user） |
| long_memory | 20% | reduce_top_k（段落化保留头部） | 检索结果靠前段最相关 |
| user_docs | 25% | reduce_top_k | **最低保留 1 段**（`05` §6.1.1） |
| task_results | 30% | 保序逐块放入、放不下当前块截尾并停 | 受保护块 `(text, protected=True)` **不截**（R9 确定性底稿） |
| history | 25% | 滑窗 keep_tail（保留最近） | — |

**接口**（代码为权威，`agents/context_manager.py`）：
- `estimate_tokens(text) -> int`：纯字符近似（CJK 1.5/字、ASCII 0.3/字符、其余 0.6/字符），**零第三方依赖**（踩坑 #9/#10），只用于预算判断。
- `ContextManager(context_window=4096, output_reserve=1024)`：默认对齐本地 ollama `num_ctx=4096 − ~1000 输出预留`；✅ **M14 已接管（2026-09-04）**：业务接入点（orchestrator `_cm_orch` / stat `_cm_stat`）改按 `router.context_window_for(agent_tag)` 传**路由实际窗口**（orchestrator_agent ∈ EXTERNAL_LLM_AGENTS → 外部 8192；stat 等 → 本地 4096），共享默认实例保留为兜底。
- `build_context(*, system, history, long_memory, user_docs, task_results) -> ContextResult`：`layers`（仅含调用方传入的非空层，处理结果）、`per_layer_tokens`、`truncated`；**预算内逐字节零改动**（常规输入回归零风险）；超限层打 `logger.warning`（层名/原 token/预算），**不抛业务异常**。
- `budget_for(layer)` / `budget_blocks(blocks)` / `truncate_text(text, max_tokens, mode)`：按块治理的低阶入口（collect 用）。

**上游调用方（连接）**：
1. `agents/orchestrator/nodes.py::plan_node`：history + long_memory 两层治理（超限才触发；组件异常回退原始拼装）。
2. `agents/orchestrator/nodes.py::collect_node`（`EXTERNAL_LLM_ENABLED` 分支）：任务结果层按块治理（多 worker 结果拼接超长时保序截尾，保留头部结论；数字白名单随治理后块计算）。
3. `agents/stat_agent/nodes.py::build_stat_prompt`：history 层滑窗（超长历史保留最近）。

**下游/依赖**：无（组件不 import 任何项目内模块，无状态纯函数，可跨 async 安全复用）。

**⚠️ 不覆盖（M12 范围外，`08` §8.2/`11` 登记）**：摘要式压缩（先只做"预算 + 截断"）；最终窗口守卫（system+user_input 主体本身超窗时组件不兜底——各层上限只保护辅助层；依赖 M14 harness / 模型侧行为）。

```text
  Ctrl+C / shutdown_system()
  → SHUTDOWN_FLAG=True → cancel 全部 worker task
  → ★M3：stop_mcp_servers() —— terminate 3 个常驻服务（5s 宽限→kill）
  → 收拢退出
```

**MCP 常驻服务的生命周期约束**（M3）：

| 项 | 契约 |
|---|---|
| 端口 | `config.MCP_SERVER_PORTS` = `BILLAGENT_MCP_PORT`（默认 8000）+1/+2/+3（bill/llm_base/llm_finance），需未被占用 |
| 谁负责拉起 | **`bootstrap_all()`**（生产入口）与 **测试 fixture**（`tests/e2e/conftest._mcp_servers`）——⚠️ e2e 直调 graph **不走 bootstrap**，必须自行拉起（M3 踩坑 4） |
| 回滚 | `BILLAGENT_MCP_STDIO=1` → 客户端走 stdio 短连接 + server 走 `mcp.run()`（**两端配对**，M3 踩坑 3） |
| 跨 loop | 用 `subprocess.Popen`（同步），**禁用** `asyncio.create_subprocess_exec`（跨 loop 启停会崩，M3 踩坑 5） |
| 孤儿进程 | 退出必须调 `stop_mcp_servers()`；异常退出时依赖 OS 回收 |
