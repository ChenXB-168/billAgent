## 二、架构结论

### 2.1 T-1 原假说为何被证伪（★核心论证）

**原假说**：「高频动词"花"拉高了无关文档的分数」。
**实测反证**（`userDocs/` 172 chunk 的 df 统计）：

```
高 df 词（≥15%）只有 6 个：。 (87.2%) ， (83.7%) 元 (52.3%) 的 (31.4%) 我 (29.7%) ： (20.9%)
★"花" 的 df = 4（2.3%）、IDF ≈ 3.65 —— 它是**稀有词**，不是高频词
```

**真正的失配**：

```
查询「每天交通花多少」分词 = [每天, 交通, 花, 多少]
期望文档「工作日通勤坐地铁，单程 4 元，一天来回 8 元左右…」分词
    = [工作日, 通勤, 坐地铁, 单程, 4, 元, 一天, 来回, 8, 左右, 偶尔, 赶时间, 才, 打车]
★查询词 ∩ 期望文档词 = ∅        ← 零重叠 = 词汇鸿沟
★查询词 ∩ top1        = {花}     ← top1 只是"恰好含'花'"
```

**→ 属**词汇鸿沟**，纯词法路原理上无法解决；且**停用词过滤也无用**（A/B：标点过滤后
hit@3 97.96% → **95.92%**、MRR 0.8571 → 0.8554，**反而变差**）。

### 2.2 D28 两个改动的实证依据（★三场景对照）

同一语料（`userDocs/` 65 篇 / 172 chunk）与同一 50 条 GT，仅改索引状态与权重：

| 场景 | hit@1 | hit@3 | hit@5 | recall@5 | MRR@5 | vector_ok |
|---|---|---|---|---|---|---|
| **S1** 模型可用 + 两路等权（改动前） | 75.51% | 97.96% | 97.96% | 96.00% | 0.8571 | True |
| **S2** 模型可用 + `vec_w=1.5`（D28-a） | 75.51% | 97.96% | **100.00%** | **98.00%** | **0.8612** | True |
| **S3** **禁用模型**（模拟残缺索引，D28-b） | **51.02%** | 83.67% | 91.84% | 90.00% | 0.6793 | False |

**关键读法**：
- **S1 → S2**：加权使 hit@5 达 **100%**、recall@5 +2pp（**D28-a 的收益**）；
- **S1 → S3**：**仅因索引缺向量**，hit@1 掉 **24.49pp**（**D28-b 的代价**）——
  且这**不是假设**：修复前 `userDocs/.index` 的真实状态就是 `vector_ok=False`、`faiss.index` **0 字节**，
  而**任何一次直接跑评测都会拿到 S3 的分数**，使用者却以为是"完整链路"。

**`vec_w` 取值依据**（跨语料交叉验证，吸取 M24「单语料 A/B 会骗人」的教训）：

| vec_w | 真实库（65 篇）hit@5 | fixture（55 篇）hit@1 |
|---|---|---|
| 0.5（偏词法） | 95.92% ↓ | 67.57% ↓ |
| 1.0（等权，原状） | 97.96% | 81.08% |
| **1.5（采用）** | **100.00%** | 81.08%（持平） |
| 2.0 / 3.0 | 100.00% | 81.08% |

**→ 两套语料同向或中性；1.5 与 2.0/3.0 结果相同（已饱和），取**温和值**更稳。**

### 2.3 为什么"缺向量"必须**强制**自愈（★自愈盲区）

`load_user_docs` 原有的向量校验**只在模型已加载时**进行 —— 这是为冷启动速度刻意设计的
（避免"为校验而启动即加载模型"）。但它带来一个**自愈盲区**：

```
启动对账（模型尚未加载，懒加载未触发）
   └─ 跳过向量校验 → 直接加载磁盘索引（vector_ok=False）
        └─ 索引安装完成，此后**不再有对账**
             └─ 首次检索虽会加载模型，但**已无人再校验索引** → 残缺状态固化  ✗
```

**→ 修法：当磁盘索引标记为"无向量"且 `EMBEDDING_ENABLED` 为真时，**强制探测一次**
（代价 = 一次模型加载）以触发重建。这是**单向**的：`vector_ok=True` 的索引仍走原懒加载路径，
**不拖慢正常冷启动**。

## 六、风险点

| # | 风险 | 说明与对策 |
|---|---|---|
| **R-1** | ★**两个改动混测导致错误归因** | **本次实际踩到**：`vec_w` 落地后跑评测得到 51.02%（"变差"），一度以为加权有害 —— 实为那次跑的是**残缺索引（BM25-only）**。**对策**：改动后必须**用受控环境复测**（临时副本 + 干净重建），并**逐项对照**（§2.2 三场景） |
| **R-2** | **权重调参过拟合**（50 条 GT） | 取 1.5 而非更大值（1.5/2.0/3.0 结果相同 → 已饱和）；且经**两套形态不同的语料**交叉验证（§2.2 表） |

| **R-4** | **`EMBEDDING_ENABLED=False` 时误加载模型** | 自愈分支显式判断该开关；且用例锁定"关闭时不越权" |
| **R-5** | **向量路权重过高淹没词法路** | 实测 `vec_w=0.5`（反向）会崩到 55.10%，说明**两路都不可废**；1.5 是温和偏向，词法路仍有效（`_RRF_BM25_WEIGHT=1.0`） |
| **R-6** | **索引缺向量本身未告警** | 本次只做**自愈**（重建），未加显式 WARNING —— 属可观测增强，登记为 §八 T-1 |
